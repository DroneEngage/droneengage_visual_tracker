# Tracker Module Messages Documentation

## Overview

This document details all DroneEngage protocol messages handled and generated by the Tracker module. The tracker processes both direct tracking commands and per-frame AI observation frames for coordinated object tracking functionality.

## Message Dependencies

### AI Perceiver Integration
The tracker module depends on AI perceiver modules (de_perceive, de_ir_camera) for object detection and tracking:

**Message Filter Configuration** (from `main.cpp`):
```cpp
#define MESSAGE_FILTER {TYPE_AndruavMessage_TrackingTarget_ACTION,\
                        TYPE_AndruavMessage_TrackingTargetLocation,\
                        TYPE_AndruavMessage_TargetTracking_STATUS,\
                        TYPE_AndruavMessage_AI_Recognition_STATUS,\
                        TYPE_AndruavMessage_AI_OBSERVATIONS,\
                        TYPE_AndruavMessage_CONFIG_ACTION, \
                        TYPE_AndruavMessage_DUMMY}
```

**Dependency Flow**:
```
AI Perceiver Module → Tracker Module → GCS/Controller
     ↓                       ↓              ↓
AI Observations → Track Processing → Status Updates
```

## Input Messages (Handled by Parser)

### 1. TYPE_AndruavMessage_TrackingTarget_ACTION (1042)
**Purpose**: Direct tracking control commands

**Message Structure**:
```json
{
  "mt": 1042,
  "ms": {
    "a": <action_id>,
    "b": <float>,  // X coordinate (POINT/REGION)
    "c": <float>,  // Y coordinate (POINT/REGION)  
    "d": <float>,  // Width (REGION only)
    "e": <float>,  // Height (REGION only)
    "r": <float>   // Radius (POINT only)
  }
}
```

**Supported Actions**:

| Action ID | Action Name | Description | Parameters |
|-----------|-------------|-------------|------------|
| 0 | `TrackingTarget_ACTION_TRACKING_POINT` | Track circular region | `b,c,r`: X,Y,Radius |
| 1 | `TrackingTarget_ACTION_TRACKING_REGION` | Track rectangular region | `b,c,d,e`: X,Y,Width,Height |
| 2 | `TrackingTarget_ACTION_TRACKING_STOP` | Stop tracking | None |
| 3 | `TrackingTarget_ACTION_TRACKING_PAUSE` | Pause tracking | None |
| 4 | `TrackingTarget_ACTION_TRACKING_ENABLE` | Enable tracking | None |
| 5 | `TrackingTarget_ACTION_TRACKING_QUERY_CONFIG` | Request configuration | None |
| 6 | `TrackingTarget_ACTION_TRACKING_AI_DRIVER_ENABLED` | Enable AI priority mode | None |
| 7 | `TrackingTarget_ACTION_TRACKING_AI_DRIVER_DISABLED` | Disable AI priority mode | None |

**Parser Location**: `tracker_andruav_message_parser.cpp` - `parseCommand()` method

### 2. TYPE_AndruavMessage_AI_Recognition_STATUS (1077)
**Purpose**: Receive AI recognition status updates from perceiver modules

**Message Structure**:
```json
{
  "mt": 1077,
  "ms": {
    "a": <status_code>
  }
}
```

**Status Codes**:
- 0: `TrackingTarget_STATUS_AI_Recognition_LOST`
- 1: `TrackingTarget_STATUS_AI_Recognition_DETECTED`
- 2: `TrackingTarget_STATUS_AI_Recognition_ENABLED`
- 3: `TrackingTarget_STATUS_AI_Recognition_DISABLED`

**Processing**: Updates tracker's AI status and adjusts tracking behavior accordingly. 
**AI Feedback Integration**: Uses `m_tracker_main.setAITrackerStatus(status)`  to synchronize AI recognition status with the tracking engine.

### 3. TYPE_AndruavMessage_AI_OBSERVATIONS (6546)
**Purpose**: Receive per-frame observation lists from AI perceiver modules (de_perceive, de_ir_camera). Replaces the removed AI_Recognition_TargetLocation (1078) best-box message.

**Message Structure**:
```json
{
  "mt": 6546,
  "ms": {
    "cam_id": "<camera id>",
    "tm_capture": <int>,
    "obs": [
      {
        "cls": "<class label>",
        "conf": <float>,
        "box": [<x>, <y>, <w>, <h>],
        "trk": <int>,
        "cls_id": <int>,
        "attrs": {}
      }
    ]
  }
}
```

`obs` carries every detection of the frame (it may be empty); `cls` and
`conf` are required, `box` is normalized [0..1] with TOP-LEFT origin in the
unrotated sensor frame (`x+w<=1`, `y+h<=1`), `trk`/`cls_id`/`attrs` are
optional.

**Processing**:
- Frames are strict-parsed (`obsParse` in `de_common/helpers/obs.hpp`); any entry missing `cls`/`conf` or with an out-of-range box rejects the whole frame.
- The lock-on target is chosen by `trk` (or the first confirmed track of the locked class) and seeded from that observation's `box`; the pixel tracker then holds it.
- Re-acquire = the same `trk` reappearing after a loss.

**AI Feedback Integration**:
The tracker module uses AI observations to update tracking in real-time:
1. **Status Updates**: `m_tracker_main.setAITrackerStatus(status)` synchronizes AI recognition status with the tracker
2. **Observation Updates**: confirmed `obs` entries feed the lock-on selection and re-seed logic
3. **Coordinate Processing**: `box` is already in the stack-wide TOP-LEFT [0..1] convention of the unrotated sensor frame

### 4. TYPE_AndruavMessage_RemoteExecute (1005)
**Purpose**: Execute remote commands on the tracker module

**Message Structure**:
```json
{
  "mt": 1005,
  "ms": {
    "C": <command_id>
  }
}
```

**Current Implementation**: Debug logging only (placeholder for future expansion)

## Output Messages (Generated by Facade)

### 1. TYPE_AndruavMessage_TrackingTargetLocation (1043)
**Purpose**: Send current tracking target location

**Message Structure**:
```json
{
  "mt": 1043,
  "ms": {
    "t": <targets_data>,          // centred (-0.5..0.5) guidance deltas
    "box": [<x>, <y>, <w>, <h>],  // tracked box, TOP-LEFT [0..1] convention
    "trk": <int>                  // locked obs track id, when locked
  }
}
```

**Generated By**: `sendTrackingTargetsLocation()` - Sends current tracked object locations

**Facade Location**: `tracker_facade.cpp`

### 2. TYPE_AndruavMessage_TargetTracking_STATUS (1044)
**Purpose**: Send tracker status information

**Message Structure**:
```json
{
  "mt": 1044,
  "ms": {
    "a": <status_code>,
    "b": <camera_direction>
  }
}
```

**Status Codes**:
- Various tracking states (implementation-specific)
- Camera direction indicates tracking orientation

**Generated By**:
- `sendTrackingTargetStatus()` - Sends current tracking status
- `sendTrackingConfig()` - Sends configuration response

**Facade Location**: `tracker_facade.cpp`

## Message Flow Diagrams

### Direct Tracking Control Flow
```
GCS/Controller → Tracker Module
├── TrackingTarget_ACTION (1042) - POINT with coordinates
│   └── Response: TrackingTargetLocation (1043) with tracked position
├── TrackingTarget_ACTION (1042) - REGION with bounds
│   └── Response: TrackingTargetLocation (1043) with tracked region
├── TrackingTarget_ACTION (1042) - STOP
│   └── Response: TargetTracking_STATUS (1044) with stopped status
└── TrackingTarget_ACTION (1042) - QUERY_CONFIG
    └── Response: TargetTracking_STATUS (1044) with config data
```

### AI Perceiver Integration Flow
```
AI Perceiver Module → Tracker Module → GCS/Controller
├── AI_OBSERVATIONS (6546) - obs[]: per-frame detections
│   └── Processing: lock-on select by trk/class, seed pixel tracker
└── AI_Recognition_STATUS (1077) - Status updates
    └── Processing: Update AI tracker status
```

### Combined Tracking Flow
```
AI Perceiver → Tracker → GCS
Observations → Processing → Status Updates
      ↓           ↓           ↓
    Objects → Coordinates → Location Reports
```

## AI Perceiver Integration Details

### Message Processing
1. **Receives Observations**: Strict-parses `AI_OBSERVATIONS` (6546) frames via `obsParse`; invalid frames are dropped whole
2. **Lock-On Selection**: Picks the target by `trk`, or the first confirmed track of the locked class, seeded from its `box`
3. **Updates Tracking**: The pixel tracker then holds the target; the same `trk` reappearing re-seeds it
4. **Status Synchronization**: Maintains AI status for coordinated behavior

### Coordinate Convention
`obs[].box` uses the stack-wide normalized TOP-LEFT [0..1] convention of the
unrotated sensor frame (`x+w<=1`, `y+h<=1`). The tracker's own
`TrackingTargetLocation` (1043) output echoes the tracked box in the same
convention, while its `t` guidance deltas remain centred (-0.5..0.5) for
`de_mavlink`'s tracking PID.

### Debug Integration
- Logs observation frames for comprehensive debugging
- Highlights lock-on selection and re-seed events
- Provides visibility into AI-tracker interaction

## Compatibility Notes

- **AI Perceivers**: Compatible with any module emitting `AI_OBSERVATIONS` (6546): de_perceive (ONNX/IMX500), de_ir_camera hotspots; the legacy `droneengage_yolo_ai` Hailo module still emits the removed 1078 message until its own migration
- **Protocol Version**: Compatible with DroneEngage v2.x
- **Message Format**: Uses nlohmann/json library for serialization
- **AI Integration**: Seamless integration with any AI perceiver module following the standard obs protocol
